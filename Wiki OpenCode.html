ZoneCe que c'est
① TabsUne conversation (« session ») par onglet. Ctrl+Tab pour passer de l'une à l'autre.
② ConversationTes messages, la réflexion du modèle (Thought), ses actions (Explored, Read, Write, execute…) et ses réponses.
③ PromptLà où tu écris. En dessous : le profil (agent : Build) et le modèle utilisés.
④ SidebarContext = mémoire de travail utilisée (25 % = il reste de la place) ; MCP = outils branchés. Ctrl+X puis B pour l'afficher/masquer.
Barre du basesc interrompt l'agent, ctrl+p ouvre la palette de commandes.

✍️ Écrire

Enter envoie.
Shift+Enter ou Ctrl+J = retour à la ligne.
Flèche ↑ = rappeler tes messages précédents.

📎 @ = joindre un fichier

Tape @ puis le nom : @projets/play-bubble/LISEZ-MOI.md.
Une partie seulement : @fichier.py#20-45 (lignes 20 à 45).

💻 ! = commande directe

Au début d'un prompt vide : !dir projets. La commande part tout de suite (c'est toi qui la tapes), et son résultat reste dans la conversation. Esc pour sortir de ce mode.

⏹️ Interrompre

Esc arrête l'agent en cours de route. Pendant qu'il travaille, Enter lui envoie une correction immédiate ; Ctrl+X puis Enter la met en file d'attente pour après.

🔀 Changer de profil

Shift+Tab passe au profil suivant : Build → Plan → reverse-web…
(Tab tout seul ne fait rien ici.)

À quoi sert Ctrl+P ?

C'est la command palette (fenêtre « Commands ») : la liste de toutes les actions possibles là où tu es, rangées par groupes. Tape dans Search pour filtrer, ↑↓ pour choisir, Entrée pour lancer, Esc pour fermer. À droite : le raccourci clavier quand il existe (ctrl+x l = Ctrl+X puis L).

Chaque action est expliquée en détail dans l'onglet Référence complète.

La palette s'adapte : dans une liste (sessions, modèles…) ou dans la visionneuse de diff, d'autres actions apparaissent. Ctrl+Alt+K (which-key) montre les raccourcis valables à l'endroit où tu es.

Une session = une conversation

Chaque session garde son historique, ses fichiers touchés et sa mémoire. Elles sont enregistrées dans D:\IA LOCAL\.donnees\ (rien n'est perdu quand tu quittes).

  1. Nouvelle conversation : Ctrl+X N, /new, ou relancer Lancer l'agent.cmd et taper N dans le menu.
  2. Lui donner un nom clair tout de suite : Ctrl+R ou /rename Play-bubble : analyse API. Sinon un titre est généré automatiquement.
  3. Retrouver une ancienne conversation : Ctrl+X L ou /sessions → la liste avec titres. Dans cette liste : Ctrl+F = épingler en haut, Ctrl+D = supprimer.
  4. Plusieurs à la fois : chaque session ouverte a son onglet en haut ; Ctrl+Tab ou Ctrl+1…9 pour passer de l'une à l'autre.
  5. Reprendre en démarrant : Lancer l'agent.cmd affiche le menu de tes conversations (titre + « il y a … ») : Entrée = la dernière, un numéro = celle-là, N = nouvelle, Q = quitter.

Exemple de noms qui aident à s'y retrouver

Au lieu deÉcris
« Check site web avec authentification REA »Play-bubble · 1 · structure et API
« Python script help »Outil HAR · script endpoints
« New session »Test · essai rapide (à supprimer)

Format conseillé : Projet · étape · sujet. Le même nom de projet que le dossier projets\<nom>\.

Mémoire pleine ? (Context dans la sidebar)

Le modèle a 96 k tokens de mémoire. Au-delà de ~80 %, OpenCode résume automatiquement le début (compaction). Tu peux le faire toi-même avant avec /compact, ou mieux : nouvelle session pour une nouvelle étape, en lui disant de relire le LISEZ-MOI.md du projet.

Ouvrir les réglages

Ctrl+P → Open settings (ou /settings). Choisis une ligne avec ↑↓, change la valeur avec ←→ ou Entrée. C'est enregistré tout de suite dans D:\IA LOCAL\config\opencode\cli.json.

FichierContientQui le modifie
cli.jsonL'interface : les 35 réglages ci-dessous + raccourcisToi, via Open settings
opencode.jsonLe cerveau : modèles, MCP, permissions des outils, profilsClaude (ou toi avec précaution), puis /reload. Pas de commentaires dedans.

OpenCode propose normalement aussi des modèles gratuits en ligne (opencode/big-pickle, …-free) : ils sont masqués chez toi (règle policies dans opencode.json : tout fournisseur refusé sauf ia-locale). /models ne montre donc que tes modèles locaux : ia-locale/agent, ia-locale/code et ia-locale/heretic. Même un fournisseur ajouté par /connect resterait bloqué.

✅ Bonnes habitudes

  • Une session par étape, avec un nom clair.
  • Profil Plan d'abord pour les grosses missions.
  • /undo si le résultat ne te plaît pas : il annule aussi les fichiers.
  • /compact ou nouvelle session quand Context dépasse 70 %.
  • Lis chaque commande avant de dire « Allow ».

🚫 À éviter

  • Permissions → auto accept sans avoir lu ce qu'il implique (onglet Settings) : il ne te demandera plus rien.
  • « Allow always » sur une commande qui supprime ou installe.
  • /connect, /pair --remote, /plugins sans savoir ce que c'est.
  • /cd vers un dossier hors de D:\IA LOCAL.
  • /update : demande plutôt à Claude (installation portable particulière).

Quand il te demande une permission

ChoixEffet
Allow onceAutorise cette commande seulement conseillé
Allow alwaysAutorise ce type de commande pour la suite du projet (sans redemander)
RejectRefuse (et annule les autres demandes en attente)

Ça bloque ?

Il ne répond plusEsc, puis réessaie. Le 1er message après une pause prend ~10 s (rechargement du modèle).
MCP « Failed » dans la sidebar/mcps pour le reconnecter.
Config modifiée/reload ou quitter/relancer.
Tout est lentFerme les jeux (VRAM), ou F2 pour passer sur le modèle code (plus rapide).
